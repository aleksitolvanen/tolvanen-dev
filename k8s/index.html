Five things worth remembering

1. Only a VM adds a kernel

A container is not virtualisation. kind, k3d, k3s and minikube --driver=docker on Linux add no kernel at all — every pod runs on your host kernel. minikube-kvm2, Docker Desktop, Rancher Desktop, Colima, OrbStack, podman machine, WSL2 and every cloud node give you a second one.

2. Container depth is what hurts

k3s on bare Linux crosses 1 container boundary. kind and minikube-docker cross 2: the node container, then the pod. Every extra layer is one more containerd, one more runc and one more image cache to keep in sync.

3. Find the kubelet and you know the architecture

kind: a systemd unit inside the node. k3s and k3d: a goroutine inside a single k3s server process — ps shows no kubelet line at all. minikube --driver=none: a systemd unit on your host. vcluster: the host cluster's real kubelet. kwok: there isn't one.

4. cgroup v2's "no internal processes" rule explains most nesting bugs

A non-root cgroup can only distribute resources to its children if it has no processes of its own. kind sidesteps this by letting systemd evacuate processes into /init.scope; k3d has to do it by hand because its PID 1 is tini; and rootless needs an explicit Delegate= because delegation is a cgroup v2 mechanism that v1 never had.

5. On macOS and Windows the node IP is unreachable from the host

The Docker bridge lives inside the VM. That single fact produces minikube service's SSH tunnel, cloud-provider-kind's ephemeral localhost ports, k3d's dedicated nginx proxy container, and half of all "works on Linux" bug reports.

Bonus: EKS is not different technology

kubelet, containerd, runc, the CRI and every API object are the same upstream projects in kind and EKS — though not the same binaries: EKS ships AWS builds on Amazon Linux, kind ships Debian builds baked into its node image. What gets substituted is the layers below the kubelet (hardware, hypervisor, node, OS) and the plugins attached to it (CNI, CSI, cloud provider, identity). That position is the finding, not the count — see the note under any comparison.

Other managed clouds

All of the below are CNCF-conformant, so layers 10–14 run the same upstream projects you run under kind. What differs is the pricing model and which layers get hidden from you.

Same Kubernetes, four incompatible cost curves: per control-plane hour (GKE, AKS Standard, OVH Standard, ROSA HCP) · per worker vCPU (ROSA, $0.171 per 4 vCPU-hour) · per-core subscription (self-managed OpenShift, Tanzu, Nutanix) · free control plane, pay only for nodes (DOKS, LKE, Civo, Vultr, and Kapsule on its mutualized tier).

What else the map would be missing

The layer tree covers one cluster vertically. These live next to it and shift the ownership boundaries — worth knowing they exist.

Hosted control planes are a pattern, not a product

Running the control plane as pods in another cluster is now mainstream: HyperShift (→ ROSA HCP), Gardener (control planes as pods in a seed cluster), Kamaji, k0smotron and vcluster. It explains why per-cluster fees are falling — a control plane is no longer its own set of VMs.

Who creates the nodes

Cluster Autoscaler scales fixed ASGs; Karpenter watches unschedulable pods and launches a right-sized instance in seconds, bypassing ASGs entirely. AKS Node Auto Provisioning and EKS Auto Mode are both Karpenter. This moves the ownership boundary of the VM layer.

The bootstrap layer: Cluster API

Declarative cluster lifecycle: a management cluster plus infrastructure providers. It quietly underpins Nutanix NKP, Rancher provisioning and many vendor stacks. Locally, CAPD runs nodes as Docker containers — and is explicitly dev/test only.

KubeVirt reverses the arrow

VMs as pods (OpenShift Virtualization, SUSE Harvester). In 2025–26 this is the main destination for VMware migrations, and it inverts the usual "Kubernetes on top of VMs" direction. It runs locally on kind and minikube too.

Version lifetime is a recurring cost

Upstream ships three minors a year and patches each for ~14 months. Vendors sell time on top: EKS extended support triples the price from $0.10 to $0.60 per cluster-hour automatically, while AKS Premium sells a 24-month LTS at that same $0.60. A map that leaves this out misses the largest recurring line item.

Ingress is already the legacy layer

AKS Automatic defaults to the Gateway API from AKS 1.36, and GKE's Gateway controller is the strategic path there as well. If you are building something new, Ingress is no longer the default answer.

Cloud dev environments are a layer below the stack

Codespaces, Coder and friends hand you a machine — you run kind or k3d inside it. In Codespaces the docker-in-docker feature is what makes that possible. Note that the kubectl-helm-minikube feature's own docs warn that Codespaces does not yet support ingress port forwarding.

Dev-loop tools are not clusters

Tilt, Skaffold, DevSpace, Telepresence, mirrord and Okteto all require a cluster that already exists. The only one that creates a cluster is ctlptl, which wraps kind, k3d, minikube and Docker Desktop behind one YAML file and wires up a local registry for you.
